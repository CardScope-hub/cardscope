CARDSCOPE — LOGOWANIE SUPABASE NA GITHUB PAGES
Wersja 1 · 27.10.2026

Ta paczka dodaje stronę logowania login.html, rejestrację e-mail/hasło,
potwierdzanie e-maila, reset hasła, sesję i wylogowanie. Nie wymaga Node.js,
budowania projektu ani Cloudflare. Używa biblioteki Supabase 2.118.0 dołączonej
lokalnie w folderze vendor. Styl pasuje do obecnego CardScope.

1. UZUPEŁNIJ JEDEN PLIK

Rozpakuj ZIP. Jeśli masz już uzupełniony supabase-config.js w repozytorium,
zachowaj go. Jeśli go nie masz, zmień nazwę dołączonego
supabase-config.example.js na supabase-config.js i otwórz go w Notatniku lub VS Code.
Wpisz URL i publiczny klucz swojego projektu pomiędzy cudzysłowami:

window.CARDSCOPE_SUPABASE = Object.freeze({
  url: "https://TWOJ-PROJEKT.supabase.co",
  publishableKey: "sb_publishable_TWOJ_KLUCZ"
});

Znajdziesz je w Supabase → projekt → Connect.
Klucz jest także w Settings → API Keys → Publishable key.
Obsługiwany jest również starszy publiczny klucz anon.

NIGDY nie wpisuj service_role, sb_secret_, hasła bazy lub tokenu użytkownika.
Ten plik będzie publiczny. Klucz publishable jest do tego przeznaczony.
GitHub Pages nie odczytuje konfiguracji logowania z serwerowego pliku .env.

2. WGRAJ PLIKI NA GITHUB

W swoim repozytorium wybierz Add file → Upload files.
Wgraj pliki z paczki i folder vendor tak, aby login.html
znalazł się w tym samym miejscu co istniejący app.html.
Zachowaj strukturę folderu vendor. Nie usuwaj obecnych plików aplikacji.
Nie wgrywaj ZIP-a jako pojedynczego pliku ani dodatkowego folderu nad login.html.
Kliknij Commit changes. Zaczekaj na zakończenie publikacji w Actions.

Paczka korzysta z istniejących plików icon.svg, assets/poncho.webp
i assets/charizard.webp. Brak ilustracji nie blokuje logowania.

3. USTAW SUPABASE AUTH

W Supabase → Authentication → Sign In / Providers sprawdź, czy Email
i tworzenie nowych kont są włączone. Nie twórz własnej tabeli z hasłami.
Supabase zapisuje użytkowników w swoim systemie Auth. Samo logowanie nie
wymaga uruchamiania wcześniejszego SQL dla tabel collection i binders.

Otwórz Authentication → URL Configuration.
Site URL ustaw na rzeczywisty adres działającej strony.
Do Redirect URLs dodaj dokładny adres strony logowania.

Jeśli używasz strony głównej konta CardScope-hub, są to:
  Site URL: https://cardscope-hub.github.io
  Redirect URL: https://cardscope-hub.github.io/login.html

Jeżeli Twoja strona ma dodatkowy folder lub własną domenę, użyj tego adresu.
Przykład: https://twoj-login.github.io/nazwa-repo/login.html
Nie dodawaj przypadkowej domeny; musi to być adres, pod którym otwierasz stronę.
Nie zmieniaj domeny między wysłaniem linku i zakończeniem odzyskiwania hasła.

4. PODŁĄCZ IKONĘ PROFILU W APLIKACJI

Na GitHub otwórz app.html i kliknij ikonę ołówka (Edit).
Na samym końcu, tuż PRZED </body>, dopisz te cztery linie:

<script src="./supabase-config.js?v=1"></script>
<script src="./vendor/supabase-2.118.0.js"></script>
<script src="./auth-client.js?v=1"></script>
<script src="./auth-header.js?v=1"></script>

Zapisz Commit changes. Zrób to tylko raz, aby nie tworzyć dwóch klientów Auth.
Ten dodatek zmienia link ikony CS na login.html i pokazuje status sesji.
Nie nadpisuje app.html, ustawień PWA, Twoich zmian ani zapisanych kart.

5. SPRAWDŹ

Otwórz swoją stronę /login.html przez HTTPS.
Wybierz „Załóż konto”, wpisz pseudonim, e-mail i hasło.
Jeśli wymagane jest potwierdzenie e-maila, kliknij link z wiadomości.
Następnie zaloguj się na stronie i sprawdź widoczną nazwę/e-mail.
Odśwież stronę — sesja powinna się odtworzyć, jeśli zapis przeglądarki jest dozwolony.
Użytkownika zobaczysz w Supabase → Authentication → Users.
Sprawdź też wylogowanie i odzyskiwanie hasła.

Większość błędów jest wyjaśniona po polsku w formularzu. Jeżeli widzisz
komunikat o konfiguracji, sprawdź dwie wartości w supabase-config.js.
Jeżeli profil nadal prowadzi do /login zamiast login.html, odśwież app.html
po zakończeniu publikacji, zamknij stare okno aplikacji i otwórz stronę ponownie.
Zmiany pliku konfiguracji mogą wymagać twardego odświeżenia przeglądarki.

6. WIADOMOŚCI E-MAIL

Domyślna wysyłka Supabase służy do testowania, ma niski limit i obsługuje
tylko dozwolone adresy zespołu projektu. Do rejestracji innych osób i resetu
ich haseł skonfiguruj własne SMTP w Authentication → Email → SMTP Settings
(nazwa sekcji może się różnić). Użyj ustawień otrzymanych od dostawcy poczty.
Nie rozwiązuj problemu wyłączaniem potwierdzeń adresu e-mail.
Jeżeli włączysz CAPTCHA w Supabase, trzeba też dodać widget CAPTCHA do formularza;
ten pakiet nie ma klucza witryny CAPTCHA i nie zawiera tej integracji.

CO TEN PAKIET ROBI Z DANYMI

Konto jest prawdziwym kontem Supabase Auth; hasła wysyła bezpośrednio biblioteka
Supabase przez HTTPS. Nie zapisujemy haseł w plikach ani w konsoli.
Sesję i token odświeżania przechowuje standardowy klient Supabase w przeglądarce.
Kod wymaga potwierdzenia użytkownika przez auth.getUser() przed pokazaniem konta.

To etap LOGOWANIA, NIE migracja danych aplikacji. Kolekcja i bindery obecnej
wersji GitHub Pages nadal pozostają w jej lokalnym magazynie. Konta Supabase
nie rozdzielają jeszcze tych lokalnych kart między osobami używającymi tej
samej przeglądarki. Nie twierdzimy, że karty są zapisane na koncie Supabase.
Nie ma też blokady dostępu do statycznego app.html; samo ukrycie interfejsu
logowaniem nie zabezpiecza danych. Docelowe prywatne dane wymagają reguł RLS
i oddzielnej integracji zapisu/odczytu. Starsze /api/… nadal nie działają
na GitHub Pages bez osobnego backendu.

W tym kroku nie zmieniono oryginalnej strony hostowanej przez Sites.
Nie podłączono Twojego projektu na żywo: nie podano jego URL ani klucza.
Nie zmieniono Twojego repozytorium GitHub — wgraj tę paczkę według kroków 1–4.

DLA PROGRAMISTY

auth-client.js: konfiguracja, klient SDK, walidacja sesji, operacje Auth,
obsługa PASSWORD_RECOVERY, brak await w callbacku onAuthStateChange.
auth-page.js: formularze, stany oczekiwania, reset pól hasła, tekstowe renderowanie.
auth-header.js: link profilu i informacja o rzeczywistym zakresie synchronizacji.
login.html/auth.css: responsywny widok bez zewnętrznych fontów i skryptów CDN.
vendor/supabase-2.118.0.js: przypięta oficjalna biblioteka przeglądarkowa.
Biblioteka używa flowType: implicit dla statycznej strony klienckiej;
powroty z e-maila kierują wyłącznie do login.html obok pliku auth-client.js.
Linki next/returnTo z parametrów użytkownika nie są wykonywane.

Dołączone testy: node --test tests/auth.test.cjs (wymaga Node.js 22.13+).
11 testów automatycznych wykonano z kontrolowanymi odpowiedziami SDK. Obejmują
odrzucenie klucza tajnego, potwierdzanie sesji, błędne hasło, rejestrację bez
sesji, reset hasła, konflikt z wylogowaniem, callbacki i formularz.
Nie przetestowano prawdziwej wysyłki poczty ani logowania w Twoim projekcie.
Podgląd wizualny przeglądarki w środowisku wykonania jest niedostępny.
